# Persistent service with explicit refresh

TokenInsights runs one native Go service per canonical database path. Bare invocation ensures that service and prints its URL; `view` is the local TUI. Managed startup re-executes the binary with inherited configuration/readiness descriptors, detaches the child, and returns only after ownership and listeners are ready. `service run` uses the same runtime in the foreground. Startup initializes missing storage but never discovers sources, syncs, or repairs existing data.

The service composes a transport-independent application controller, public HTTP handlers, and a private Unix control socket. A lifecycle admission lock prevents simultaneous startup and standalone maintenance; a lifetime lock establishes ownership; the existing writer lock protects actual pipeline/reset writes. Lock inodes remain persistent. Status verifies ownership and a live instance handshake without creating files. Occupied ports and unreachable owners fail without killing another process or bypassing ownership.

Ordinary refresh requests share active work before source capture. Later requests coalesce into one follow-up. Explicit CLI sync/normalize retain their caller's source configuration and options in a bounded FIFO. Accepted refresh survives viewer disconnect. There is no periodic refresh, watcher, or automatic startup ingest. Every normal TUI opening requests refresh; web opening reads saved data, and Refresh requests ingest. Future harness hooks can use the same refresh boundary without introducing another writer.

Source configuration captures absolute I/O paths and lexical identity paths once. Default dashboard refresh uses saved roots; forwarded CLI maintenance uses caller roots without changing saved configuration. Source IDs, recovery fingerprints, token semantics, SQLite schema 14, and data generation 5 remain unchanged.

Public snapshots carry runtime instance, data epoch, and durable revision. Destructive actions drain public read permits before changing epoch and writing. Browser keys include instance/epoch; local TUI reads sample service identity around their SQLite transaction. TUI observation cancellation never cancels shared work. Explicit reset cancels queued ordinary refresh and rejects new ordinary requests until completion, preventing accidental reimport.

Pending requests and deduplication are process-local and bounded; a daemon crash loses queued demand. Durable pipeline jobs still report interrupted work. Login/reboot autostart, authentication, plugins, IPv6, durable job queues, and SQL pagination changes remain deferred. Wildcard IPv4 binding is intended for trusted networks. Administration stays on the local Unix socket; same-origin protection limits browser mutation requests but supplies no authentication.

This adds lifecycle complexity and a Go application boundary, while retaining direct native builds and existing SQL/pipeline behavior. Historical content verification can still read large source histories on explicit refresh; persistence removes repeated startup/ingest work without weakening continuity checks.
