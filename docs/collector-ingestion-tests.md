# Collector ingestion failure tests — proposed

Status: design and fixture work. Canonical ingestion does not exist yet. The fixtures below are candidate behavioral examples, not an approved wire protocol, schema, or executable server coverage. No ingestion guarantee is implemented by adding these files.

Guarantee IDs refer to [the architecture proposal](collector-server-architecture.md). Failure IDs stay stable when tests are added. Planned production failure coverage is tracked in [issue 03](../.scratch/collector-ingestion/issues/03-real-ingestion-failure-tests.md); identity and schema prerequisites are [issue 01](../.scratch/collector-ingestion/issues/01-stable-harness-identities.md) and [issue 02](../.scratch/collector-ingestion/issues/02-storage-and-wire-contract.md). This proposal changes the refresh ownership in ADR 0005; existing service tests continue to describe the current product until implementation replaces that boundary.

## Oracle and fixture ownership

Use independently reviewed golden outputs, never snapshots generated by the implementation under test. Every fixture value is synthetic. Do not copy real harness artifacts. Source fixtures retain only the record structures and metadata needed by adapters; raw facts remain local and metadata-only.

The future end-to-end oracle checks both identity and value: exact session/fact set, canonical payload, each token component, session count, and aggregate totals. Count-only assertions can miss one suppressed legitimate fact plus one accidental duplicate. Compare persisted state after closing and reopening both databases, then query through REST to prove acknowledgement means queryable.

[`collector-ingestion-protocol`](../packages/cli/testdata/conformance/collector-ingestion-protocol/README.md) contains candidate canonical payloads and operation traces. Symbolic identity labels stand in for future reproducible IDs; they do not establish a hashing algorithm. Source-derived IDs require separate adapter fixtures. Operation labels and outcome names are test vocabulary, not proposed JSON request fields or HTTP status codes.

Each planned test must name its Fxx/Gxx IDs, fixture, fault seam, independently specified outcome, and replay action. Promotion from planned to executable requires an actual collector/server path and a test that drives it; fixture parsing or a fake ingestion simulator does not qualify.

## Traceable failure matrix

| Failure | Guarantee | Candidate fixture | Required behavior |
| --- | --- | --- | --- |
| F01 Collector database deleted | G01, G02, G05 | `F01-rebuilt-collector.json` | New stream and batch IDs replay identical facts without changing usage; two equal-valued requests remain two facts. |
| F02 Commit succeeds; response lost | G05, G06, G07, G10 | `F02-lost-acknowledgement.json` | Query already shows committed facts; collector cursor stays pending; exact replay returns the saved receipt. |
| F03 Batch ID reused with different content | G05, G11 | `F03-batch-content-conflict.json` | Reject conflict; change neither facts nor original receipt. |
| F04 Same fact ID, changed payload without ordering evidence | G05, G11 | `F04-fact-conflict.json` | Diagnose conflict; preserve existing contribution; never insert another countable fact. Changed-payload policy remains to be approved. |
| F05 Concurrent submissions | G05, G06 | `F05-concurrent-duplicates.json` | Same-batch retries and different-batch identical facts each produce one contribution; conflicting batches are serialized or rejected, not last-writer-wins. |
| F06 Revisions delivered out of order | G05, G07, G11 | `F06-out-of-order-revisions.json` | Older revision cannot overwrite newer value. A delivery cursor cannot jump an unacknowledged sequence gap. Cross-stream changed values use F04. |
| F07 Same identity in different owners | G05 | `F07-owner-isolation.json` | Distinct owner partitions; authenticate/derive owner outside submitted entity data. One owner's receipt/data cannot acknowledge another's upload. |
| F08 Dangling/cross-owner references or mid-batch failure | G06, G11 | `F08-reference-integrity.json` | Entire batch rolls back; no orphan facts, partial sessions, or success receipt. Existing references or included references work regardless of array ordering. |
| F09 Incompatible publication version | G09, G11 | `F09-incompatible-version.json` | Explicit rejection before mutation; supported compatible input replays safely. Migration tests must preserve identity and contributions. |
| F10 Invalid counters | G06, G11 | `F10-invalid-counters.json` | Reject negative, fractional, overflow, contradictory total, or missing required counters without partial writes; preserve exact integers above JavaScript's safe-integer range or explicitly reject unsupported range. |
| F11 Capacity reached or SQLite busy | G06, G07, G10, G11 | `F11-admission-retry.json` | No success acknowledgement for uncommitted work; preserve local pending data; next manual sync retries. Test limit and limit+1. |
| F12 Raw/private fields in publication | G08, G11 | `F12-private-fields.json` | Collector allowlist excludes them; server rejection/logging does not persist prohibited fields or echo content. |
| F13 Durable Source absent on next sync/rebuild | G05, G10 | `F13-source-absence.json` | Publish discovered data; absence is not deletion; existing server history remains. No retraction mechanism is proposed. |
| F14 Process crash at a persistence boundary | G03–G07, G10, G11 | `F14-crash-boundaries.json` | Reopen actual databases and manually resume; every durable progress marker has its corresponding durable facts/work. |

Concurrent cases must cover one batch replayed twice, different batches with identical entities, and different contents under one batch ID. Within one batch, identical repetitions must count once and conflicting repetitions must fail atomically. Test both arrival orders for changed facts. Hold explicit barriers around validation/commit; do not rely on sleeps to create races.

## Crash boundaries

F14 has independent scenarios, not one imagined uninterrupted execution:

| Fault seam | State after reopen | Manual resume |
| --- | --- | --- |
| After parsing, before collector capture commit | Neither raw facts nor source progress advanced | Reparse source. |
| During collector capture transaction | No partial raw facts/progress | Reparse source. |
| After collector capture commit | Raw facts and continuity durable; normalization pending | Normalize captured work. |
| During canonical/journal transaction | Neither new canonical state nor publication entries committed | Normalize again. |
| After canonical/journal commit | Canonical facts and pending changes durable | Publish saved changes. |
| During immutable batch preparation | No cursor advance; committed batch bytes remain immutable | Reuse committed batch, otherwise prepare from pending journal. |
| After batch saved, before send | Saved batch and pending cursor durable | Send exact saved batch. |
| During server transaction | No partial entities/receipt | Replay saved batch. |
| After server commit, before response | Entities and receipt durable/queryable; collector pending | Replay saved batch. |
| After response, before collector acknowledgement commit | Server durable; collector pending | Replay saved batch. |
| During collector acknowledgement transaction | Batch status and contiguous cursor advance together or neither | Replay if still pending. |
| After collector acknowledgement commit | Durable cursor refers to durable server receipt | Next sync sends only remaining work. |

Use explicit injectable transaction seams plus subprocess termination for representative before/after commit cases. Inject SQL failure after the first valid entity, disk/commit failure, response loss after commit, and cancellation before/during/after send. Do not simulate a crash by calling a successful graceful shutdown. Reopen SQLite/WAL state using production open paths.

Response replay must survive server restart. Cancellation and timeout have an unknown delivery outcome until retry resolves the saved batch; they never authorize cursor advancement. No background retry is required: a later manual `sync` resumes pending work.

## Current executable evidence

The root build-tools suite scans every `collector-rebuild/source` and `stages` file for synthetic metadata only, materializes both OpenCode SQL fixtures in memory, and rejects extra fields/non-synthetic labels. This fixture-safety check runs through `pnpm run test`; it is privacy/fixture evidence, not server ingestion coverage.

The new [collector rebuild fixture](../packages/cli/testdata/conformance/collector-rebuild/README.md) drives the existing production adapters, SQLite persistence, and normalization. Its independent golden oracle contains 12 facts totaling 1102 tokens. Exact canonical semantic identities and values are compared across repeated parsing and database reconstruction.

| --- | --- | --- |
| CFI-001 Baseline | `TestCollectorRebuildFixture` | Pass: exact facts/components/provenance/diagnostics. |
| CFI-002 100 forced reparses | `TestCollectorRebuildRepeatedSyncPreservesFactsAndIdentities` | Pass: identities and values preserved at advancing clocks. |
| CFI-003 Fresh databases | `TestCollectorRebuildFreshDatabaseAtDifferentClocks` | Pass: unchanged sources reproduce values and identities. |
| CFI-004 Retained raw-only rebuild | `TestCollectorRebuildNormalizeRetainedRawWithoutSources` | Pass: normalization succeeds without Durable Sources. |
| CFI-005 Moved artifacts | `TestCollectorRebuildMovingArtifactsPreservesFacts` | Pass: retained native identities survive relocation. |
| CFI-006 Copied Pi/Claude artifacts | `TestCollectorRebuildCopiedArtifactsDoNotMultiplyUsage` | Pass: copies do not multiply facts. |
| CFI-007 OpenCode equal timestamps | `TestCollectorRebuildOpenCodeEqualTimestampDistinctNativeRequests` | **Fail: 2 facts instead of 3.** Distinct native requests are suppressed. |
| CFI-008 Claude streaming completion across syncs | `TestCollectorRebuildClaudeAppendMatchesFreshFinalParse` | **Fail: 2 facts instead of 1.** Partial and completed usage both contribute. |
| CFI-009 Pi missing message IDs | `TestCollectorRebuildPiMissingIDsRetainRawEvidence` | Pass for raw retention and missing-ID diagnostics only. Canonical counting/fallback policy pending. |

CFI-007/008 failures are implementation blockers, not golden-output mistakes. Keep them failing until correct behavior is implemented; do not weaken or skip assertions. CFI-008 concerns changed source content across syncs, not nondeterminism when identical bytes are reparsed into empty databases. Independent review rejected an initial CFI-009 assertion requiring two canonical facts: different counters without native IDs cannot prove independent requests. That fixture remains; canonical ambiguity handling is pending in issue 01. CFI-003 proves the unchanged-source reconstruction case for this dataset, not every possible harness artifact.

Reproduce all nine from `packages/cli`:

```sh
go test ./internal/pipeline -run '^TestCollectorRebuild' -count=1 -v
```

## Implementation gates

1. Finalize reproducible identity rules using harness fixtures. Exclude collection time, local row IDs, transport/installation IDs, source paths, and token values from logical identity. Prove fresh-database reparse equality at different wall-clock times.
2. Approve schema/protocol changes explicitly. Add real storage and HTTP tests driven by these traces. Preserve current local conformance coverage during extraction into the collector.
3. Add transaction fault seams and immutable-batch replay tests before exposing ingestion. Check persisted identities/values, exact receipts, REST totals, and safe diagnostics at each boundary.
4. Run generated permutations of batch boundaries, retries, entity order, arrival order, and restart positions against the same golden final state. Preserve independently authored golden fixtures as the oracle.
5. Exercise the built Go collector and local server end to end in isolated fixture directories. Normal sync, server offline then manual retry, and collector database deletion must produce the same canonical set and totals.

Record failures with safe correlation metadata: collector stream, journal sequence range, batch ID, identity-rule/protocol version, fact ID, stage/error code, and aggregate counts. Retain receipts across restart. Do not log raw artifacts, request bodies, full source paths, secrets, or conversation fields. Tests should assert correlation metadata survives the relevant boundary.
