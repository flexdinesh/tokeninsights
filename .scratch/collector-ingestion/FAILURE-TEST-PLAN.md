# Executable collector/server failure plan

Status: implementation plan; no server ingestion coverage claimed. SQLite/wire contract approval pending.

This supplements the [architecture guarantees](../../docs/collector-server-architecture.md), [failure matrix](../../docs/collector-ingestion-tests.md), and [candidate traces](../../packages/cli/testdata/conformance/collector-ingestion-protocol/README.md). Test names below are proposed; package placement follows the approved production boundaries. Fxx/Gxx references belong in test comments and failure messages so a failed assertion identifies its architectural requirement.

## Independent oracles

Maintain two distinct fixture paths:

- **Production capture path:** copy `collector-rebuild/source` into a temporary Durable Source root; materialize synthetic OpenCode SQL; run real adapters, normalization, journaling, immutable batch preparation, HTTP delivery, and REST queries. Its hand-authored oracle is 12 facts, input 800, output 148, reasoning 52, cache read 96, cache write 6, total 1102. Compare the complete expected fact/session sets and token components, not only the total. Expected identities must come from the approved identity specification, independent of the production ID helper.
- **Protocol adversary path:** translate `canonical-inputs.json` labels to approved typed payloads and submit to the production HTTP handler with real file-backed SQLite. Fact A is `(80,20,0,0,0)=100`; distinct native request B has the same counters, independently contributing another 100. A changed is `(80,40,0,0,0)=120` under A's same logical identity. Empty state is zero facts/zero tokens; A+B is two facts and `(160,40,0,0,0)=200`; A changed+B is two facts and `(160,60,0,0,0)=220`. These literal expectations remain reviewable and never derive from an ingestion implementation.

Treat a fixture trace as an input/action/oracle specification. A test executor may resolve labels, call production APIs, invoke transport faults, reopen storage, and compare state. It must not decide expected dedupe, revision, totals, or cursor behavior through its own state machine. Seed initial history through a previously asserted real ingest; do not bypass server validation by inserting canonical rows directly. Direct SQL reads are permitted to inspect persistence and receipts.

For each accepted operation, compare exact canonical entities, their native identities, payload hashes, all token components, countability, session references, and receipts. Query REST immediately after acknowledgement, then stop/reopen both databases and query again. Ignore only explicitly operational fields such as SQLite row IDs and collector-local wall-clock audit times; do not ignore canonical timestamps, source identity, or published payload differences. Include unrelated preexisting history so rollback/reset tests detect accidental deletion.

The existing CFI001–009 real pipeline tests remain the first gate. Preserve CFI007/008 semantics while fixing OpenCode request suppression and Claude partial/final duplication. CFI009 proves raw evidence retention and diagnostics; it does not authorize inventing separate canonical requests from ambiguous missing IDs.

## Test mechanics and fault ownership

Use temporary **file-backed** SQLite databases, separate collector/server paths, real handlers, and actual HTTP clients. `httptest.NewServer` is sufficient for ordinary wire/validation tests. SQLite `:memory:` tests cannot prove crash recovery, file lifecycle, durable receipts, or process-lock behavior. Fake transports are appropriate for malformed acknowledgements only when paired with a real-server persistence test of the same successful path.

Prefer existing SQLite trigger failures for deterministic transactional rollback. `source_writer_test.go` already injects trigger failures while exercising real capture transactions. Follow that approach for approved journal, entity, receipt, batch, and acknowledgement writes. SQL triggers exist only in temporary test databases; never modify the repository schema to add fault mechanisms.

When a transaction boundary cannot be reached with SQL/transport controls, inject a narrow optional callback through an internal dependency owned by that boundary. Default behavior is no-op. No production environment-variable kill switch, public fault API, shared mutable hook, sleep-based ordering, or new generic storage abstraction is needed. Fault callbacks may block at a named barrier or return an error; they must not implement a replacement write path.

Crash tests use a helper subprocess running the real collector/server entry path with test-injected dependencies. The child signals a named barrier through a pipe and blocks; the parent verifies the signal and kills the child without graceful shutdown. The parent waits for exit before reopening the same SQLite file, including its WAL. It must not delete/checkpoint the WAL or repair storage to obtain the expected result. A bounded test timeout fails on a missing barrier; elapsed time never substitutes for observing the seam. `os.Exit` skips deferred rollback but remains a weaker companion test than an external process kill.

Server commit/response seams belong to ingestion; collector normalization/journal seams belong to the collector; source capture seams belong to pipeline; send/receipt/ack seams belong to delivery. A mutex in the test harness cannot prove durable uniqueness. Concurrent HTTP tests use independent server DB connections and repeat contention with separate server processes where supported by the approved ownership model.

## F14 seam checklist

Each subtest starts independently from clean collector state plus fixed unrelated server history. The target facts A/B appear only once after recovery. Check intermediate persisted state before resuming so an eventual correct total cannot hide an unsafe acknowledgement or lost queue.

| Observed child barrier | After kill/reopen | Required next manual action |
| --- | --- | --- |
| Before capture commit | No target raw facts or advanced source continuity marker | Capture again |
| During capture transaction, after first write | No target partial raw/observations/normalization work or advanced marker; failure audit, if separately committed, cannot claim capture success | Capture again |
| After capture commit | Captured raw evidence, matching source progress, normalization work durable; target server facts absent | Normalize and deliver |
| During canonical/journal transaction, after canonical write | No target canonical mutation or associated journal entry; normalization work remains pending | Normalize and deliver |
| After canonical/journal commit | Canonical and corresponding journal snapshots both durable; target server facts absent | Prepare/deliver |
| During immutable batch save | No delivery cursor advance; any committed batch has its complete immutable body and retry identity | Reuse saved batch or prepare from pending journal |
| After saved batch, before send | Exact retry identity/body retained; target server facts absent | Send saved batch |
| During server transaction, after first entity write | No target partial facts/session/receipt; collector batch pending | Replay saved batch |
| After server commit, before response | A+B and receipt durable/queryable; collector remains pending | Replay saved batch |
| After response, before collector ack transaction | Same as previous seam; received bytes alone cannot imply durable progress | Replay saved batch |
| During collector ack transaction, after first state write | Batch acknowledgement and contiguous destination cursor are both rolled back or both committed; never mismatch | Replay only if still pending |
| After collector ack commit | Destination cursor corresponds to durable matching server receipt; acknowledged batch not resent by ordinary sync | Deliver only later pending work |

## Additional delivery and architecture cases

These gaps supplement, rather than reinterpret, F01–F14. Assign durable case IDs in the failure matrix when implementing.

- **Destination independence (G07/G10):** create two distinct real server databases. Destination A accepts A+B; B is offline. A's validated cursor advances; B stays pending. Restart collector, keep A offline, recover B; each server ends at two/200. Changing a URL to a different server instance must not reuse progress just because the textual destination name is unchanged. Define destination identity/rebinding before implementing this test.
- **Journal snapshots (G04/G05):** prepare batch containing partial A; change canonical A before delivery. Retried batch must still have its exact original payload; later changes create later journal work. No `SELECT current canonical values` may mutate a pending retry. Changed-value acceptance remains governed by source revision policy.
- **Receipt binding (G06/G07):** use a transport that returns a syntactically successful but wrong destination/stream/batch/hash/range receipt. Cursor and pending batch remain unchanged; diagnostic identifies invalid acknowledgement. Pair with successful real-server delivery. Replaying an acknowledgement cannot advance twice or acknowledge work never submitted.
- **Acknowledged prefix (G07/G10):** force three bounded batches. Accept first, fail second, never send third. Restart/manual sync preserves first progress and delivers suffix once. Verify exact facts/components, not only the final count.
- **Collection without server (G03/G04/G10):** sync while local server cannot start or remote is offline. Captured canonical facts/journal remain; next invocation does not require original files to resend durable pending payloads. No successful delivery claim while pending work exists.
- **Collector serialization (G03/G04/G07):** two actual `sync` processes share one collector DB. Source cursors, normalization work, immutable batch creation, and destination progress remain consistent under the existing writer-lock policy. Cancellation while waiting leaves no partial progress. Two separate reconstructed collectors against one server exercise server uniqueness independently of the host lock.
- **Server isolation (G08/G10):** configure failing/spy discovery dependencies and unreadable Durable Source roots; startup and every query/ingestion request must perform zero discovery/adapter calls. Local and remote compositions instantiate the same ingestion/query core. Selecting remote must not start local service; server startup must not collect even when configured source paths exist.
- **Native identity encoding (G01/G02):** golden preimages include delimiters, Unicode, different harnesses, parent/origin distinctions, and identical counters/times with distinct request IDs. Equal tuple produces equal ID across fresh databases/clocks/locations; distinct tuples do not share ID because strings were concatenated ambiguously. Mutable labels, collection time, and delivery identities cannot affect source-derived fact identity.
- **Diagnostic distinction (G11):** capture, normalization ambiguity, compatibility, replay, fact conflict, admission, and invalid acknowledgement fail with distinct safe codes. Errors identify stage/IDs without transcript or paths. Error code tests must not depend on exact incidental SQL error text.
- **No source truth from clients (G01/G05):** server dedupe guarantees cover honest collector reconstruction and documented namespace rules. Tests cannot establish protection against a malicious uploader deliberately assigning new IDs to the same event; ownership/authentication and ID validation boundaries must be stated explicitly.

## Completion and mutation checks

Promote a case from planned only after a runnable production-path test exists, with fixture, seam, expected state, and recovery action identified. Record test commands/results in `VALIDATION.md`. Tests load and preserve candidate traces; they must fail if a trace case/variant is silently ignored. Fixture-format integrity is secondary coverage, not a substitute for these operations.

For review, make controlled local mutations separately: disable fact uniqueness (F01/F05 fail); acknowledge before server commit (F02/F14 fail); save canonical without journal (F14 fails); advance destination progress before validated acknowledgement (F02/F06 fail); use current canonical payload when retrying a saved batch (journal snapshot/F03 fail); commit first entity before validating the second (F08/F10 fail); allow forbidden fields/body logging (F12 fails). Revert mutations before verification. Mutation checks should touch production logic actually used by the tests, never the fixture executor.

Run format/lint first, then focused pipeline/ingestion/delivery/CLI tests, full tests, schema/API checks, native build, race tests, and affected browser tests. Real subprocess tests need deterministic barriers, bounded deadlines, and cleanup after expected kills; increasing sleeps is not a flake fix. A broad race suite does not replace concurrent persistence assertions.
