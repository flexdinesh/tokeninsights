# Move project directories under packages

## Summary

Restructure the repository into a pnpm-style monorepo layout by moving `plugins/`, `schema/`, `scripts/`, and `cli/` under `packages/`, then update scripts, docs, and source paths accordingly.

## Key implementation changes

- Move directories:
  - `plugins/` -> `packages/plugins/`
  - `schema/` -> `packages/schema/`
  - `scripts/` -> `packages/scripts/`
  - `cli/` -> `packages/cli/`
- Update root pnpm scripts to reference `packages/scripts/check-schema.ts` and workspace filters under `packages/`.
- Update `pnpm-workspace.yaml` package globs to `packages/plugins/*` and `packages/cli`.
- Update schema path references in source code and the schema checker.
- Update README, docs/design.md, AGENTS.md, and other active docs that reference moved paths or commands.
- Regenerate/update `pnpm-lock.yaml` for the new workspace importer paths.

## Tests and verification

Run:

```sh
pnpm install
pnpm run check-schema
pnpm run build
pnpm run test
```

## Decisions made

- Use `packages/plugins`, `packages/schema`, `packages/scripts`, and `packages/cli` as the new physical layout.
- Keep package names unchanged so plugin linking by package name remains unaffected.
- Do not change database schema contents.

## Tradeoffs and risks

- `pnpm-lock.yaml` will change because workspace importer paths changed.
- Build outputs may be regenerated by verification; keep or revert generated artifacts based on existing tracked state.
- Historical plan/decision-log docs may retain old paths unless they are active guidance.

## Execution guidance

If implementation deviates from this plan, update this plan file with the approved deviation and surface the change to the user.
