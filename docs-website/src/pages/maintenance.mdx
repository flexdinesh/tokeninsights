# Maintenance

TokenInsights keeps raw evidence and a published generation of processed usage.
SQLite uses pooled reads and a serialized WAL writer. PostgreSQL uses a dedicated
owned writer and pooled snapshot reads.

## Reprocess local data

```sh
tokeninsights data reprocess
tokeninsights data wait
```

Reprocessing is explicit, never automatic. It keeps the published generation until
the replacement is complete. Local data maintenance has a 30-second visibility wait.
If reprocessing exceeds that wait, `data wait` resumes the saved generation without
starting another rebuild. Persistent `processing_failed` errors can be recovered with
`data reprocess`. Raw evidence and the old published generation remain intact.

Keep a stopped backup of the paired databases and application guard before
maintenance.

## Backups

Application pairing persists `<canonical-token-path>.application.json`, containing
only the application instance ID. Keep this guard with both databases in stopped
backups. A missing or replaced app database fails closed to preserve credential
revocations. Restore the matched set; do not delete the guard to bypass recovery.

## Incompatible data

Only current schemas are supported. There are no imports or migrations. Storage uses
collector schema **20**, token SQLite schema **1**, PostgreSQL token/account schemas
**1/2**, personal application SQLite schema **2**, hosted application SQLite schema
**3** and job SQLite schema **1**.

When `tui`, `web`, `data`, or `sync` finds local storage written by an older version,
it asks before resetting:

```text
TokenInsights needs to reset local storage written by an older version.

  collector.sqlite   schema 19 -> 20   reset
  server.sqlite      schema 1          keep
  app.sqlite         schema 2          keep

Old files move aside:
  /home/you/.local/share/tokeninsights/collector.sqlite.v19.bak

Usage is rebuilt from saved usage and harness logs.

Reset now? [y/N]
```

Old files are moved, never deleted. Resetting the token database also resets the
application database and its pairing guard, recreating local accounts and
credentials. If the collector and token databases reset together, usage whose
harness logs were already deleted cannot be rebuilt; restore the `.bak` files to
recover it. Without a terminal (for example, plugin background syncs), the command
reports the files and changes nothing; run it once in a terminal.

Files written by a newer version, files that are not TokenInsights databases, and
files whose structure does not match are never reset. The error names each file
and the next step. Remote servers never reset storage; incompatible databases
reject without mutation.
